## Cloudflare 部署失败定位（Workers/OpenNext 误用，2026-09-02）
- 用户按 Workers 方式部署（`npx wrangler deploy`）→ wrangler 检测 Next.js 自动走 OpenNext 迁移（云端生成 wrangler.jsonc/open-next.config.ts/.dev.vars 并改 package.json/next.config.ts）→ `opennextjs-cloudflare build` 在 Bundling cache assets 步报 ENOENT：`/opt/buildhome/repo/.next/standalone/.next/server/pages-manifest.json`。
- **根因**：本项目 `output:'export'` 纯静态导出，`.next` 无 standalone 也无 pages-manifest.json（App Router 为 app-paths-manifest.json），OpenNext 必然失败。**本项目必须用 Cloudflare Pages（输出目录 out），禁用 Workers/OpenNext**。
- 本地仓库未被污染（无 wrangler.jsonc/open-next.config.ts/.dev.vars，package.json/next.config.ts/.gitignore 原样）。
- 修复方案：Dashboard 删除 jinkuatong Worker 项目 → 新建 **Pages** 项目连 Git（构建命令 `npm run build`、输出目录 `out`、不填部署命令）；CLI 备选 `npx wrangler pages deploy out --project-name jinkuatong`（注意是 `pages deploy` 不是 `deploy`）。

## Cloudflare Pages 首次线上部署成功（2026-09-02）
- 流程：本地构建（先 `Rename-Item .next/.next_prev_dep` + `out/out_prev_dep` 防 safe-delete 守卫）→ `npx wrangler pages project create jinkuatong --production-branch main` → `npx wrangler pages deploy out --project-name jinkuatong --branch main`。
- 结果：上传 891 文件（含 _headers/_redirects），生产 URL **https://jinkuatong.pages.dev/**（本次部署预览 5aff4d36.jinkuatong.pages.dev）；关键页（/ /companies/ /industrial-belts/ /registry/ /about/）全部 HTTP 200。

- 关键认知：Cloudflare **Pages 与 Workers 是不同命名空间**——之前云端误建的 `jinkuatong` Worker（OpenNext 失败）不影响 Pages 同名项目；`wrangler pages deploy` 要求 Pages 项目先存在，否则报 "Pages project does not exist"（非交互环境部署还需 CLOUDFLARE_API_TOKEN，OAuth 登录后免 token）。
